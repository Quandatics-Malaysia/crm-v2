## `components/` — shared UI

`apps/web/components/ui/` (32 files) is the [shadcn/ui](https://ui.shadcn.com)
primitive layer, generated via the shadcn CLI on top of
[Base UI](https://base-ui.com) — `button.tsx`, `dialog.tsx`, `select.tsx`,
`table.tsx`, `combobox.tsx`, `sidebar.tsx`, `form.tsx`, `sonner.tsx` (toasts),
and so on. `components.json` at the app root configures the CLI (aliases,
style). Treat this directory as generated/vendored: extend by re-running the
shadcn CLI or by composing these primitives in a higher-level component,
rather than hand-editing the primitives themselves unless you're
intentionally patching upstream behavior.

One level up, `components/*.tsx` holds the app-specific building blocks that
route modules compose:

- **`data-table.tsx`** — the `DataTable` component every list page uses
  (`ProjectsTable`, `quotations-table.tsx`, etc. all wrap it), built on
  `@tanstack/react-table`. Exports `SortableHeader` and `linkCell` helpers
  used directly in column defs (see `projects-table.tsx` in
  [app.mdx](/codebase/app)).
- **`detail-page.tsx`** / **`detail-skeleton.tsx`** — the detail-page shell
  and its loading skeleton.
- **`app-sidebar.tsx`** — the authenticated shell's nav. Nav items carry an
  optional `module?: ModuleId` tag; the layout computes the enabled-module
  map once and items filter themselves against it (see
  [Modules Guide](/modules/overview)).
- **`command-palette.tsx`** — the `⌘K` command palette, tagged with
  `module?: ModuleId` the same way.
- **`create-entity-dialog.tsx`**, **`quick-create-account.tsx`**,
  **`quick-create-contact.tsx`** — inline "create related record without
  leaving this form" dialogs.
- **`milestones-panel.tsx`**, **`milestone-split-dialog.tsx`**,
  **`stage-path-view.tsx`**, **`stage-progress.tsx`**, **`status-badge.tsx`**,
  **`picklist-card.tsx`**, **`object-tile.tsx`**, **`inline-value.tsx`**,
  **`inline-combobox.tsx`**, **`inline-rename.tsx`** — small, reusable
  building blocks for the record-detail UI pattern used across modules
  (inline-editable fields, status pills, picklist management).
- **`document-viewer.tsx`**, **`documents-section.tsx`**,
  **`file-dropzone.tsx`** — the attachment/file UI, paired with
  `components/attachments/attachment-upload.tsx`.
- **`empty-state.tsx`**, **`table-skeleton.tsx`**, **`forbidden.tsx`** — the
  standard empty/loading/denied states, so route modules don't each invent
  their own.
- **`mermaid.tsx`** — renders Mermaid diagrams (used by the in-app
  documentation viewer at `/documentation`).
- **`theme-toggle.tsx`**, **`text-size-toggle.tsx`**, **`site-header.tsx`**,
  **`page-header.tsx`**, **`command-palette.tsx`** — chrome.

Two subdirectories group by feature rather than by primitive:
`components/activity/` (`activity-timeline.tsx`, `change-history.tsx`,
`change-list.tsx` — rendering `logActivity`/`recordChanges` output) and
`components/attachments/` (`attachment-upload.tsx`).

**Convention:** a component used by exactly one route module lives in that
module's own directory (e.g. `app/(app)/projects/projects-table.tsx`); a
component used by two or more belongs in `components/`. When in doubt, start
it in the route module — promote it to `components/` the moment a second
module needs it.

## `hooks/` — React hooks

Small and few: `use-mobile.ts` exports `useIsMobile()`, reading
`matchMedia` via `React.useSyncExternalStore` (no `setState`-in-effect; the
SSR snapshot defaults to `false`/desktop so hydration stays stable).
`use-open-on-new-param.ts` opens a dialog/panel when a specific search param
is present (the `?new=1` deep-link pattern `projects/page.tsx` uses to
auto-open the create form). Add a hook here when a piece of client-only
stateful logic — not a data fetch, not a business rule — is shared by more
than one component; otherwise keep it local to the component that needs it.

## `tests/` — Vitest

`apps/web/tests/` is flat, and every file targets a **pure function**,
mirroring the framework-free convention in `server/services/` and parts of
`lib/`: `quotation-math.test.ts` (`computeQuotation`'s reconciliation
invariant, tax-inclusive vs. exclusive, discount clamping),
`quote-number.test.ts` / `quote-net.test.ts`, `opportunity-code.test.ts`,
`stage-gate.test.ts`, `milestone-split.test.ts`, `so-milestones.test.ts`,
`interco-share.test.ts`, `finance-kinds.test.ts`, `change-tracking.test.ts`,
`reminders.test.ts`, `status-tone.test.ts`, plus `server-only-stub.ts` — a
stub for the `server-only` package's side-effecting import so these files
can `import` a `server-only`-guarded module under Node/Vitest without it
throwing.

The pattern, from `tests/quotation-math.test.ts`:

```ts
import { describe, expect, it } from "vitest"
import { computeQuotation } from "@/server/services/quotation-math"

function assertReconciles(t: ReturnType<typeof computeQuotation>) {
  expect(t.subtotal + t.taxTotal - t.discountTotal).toBeCloseTo(t.total, 2)
  // ...per-line sums reconcile to the header too
}

describe("computeQuotation", () => {
  it("computes a simple tax-exclusive quote", () => {
    const t = computeQuotation({ lines: [{ quantity: 2, unitPrice: 100 }], ratePercent: 6 })
    expect(t.subtotal).toBe(200)
    assertReconciles(t)
  })
})
```

**What's deliberately *not* unit-tested here:** Server Actions, route
components, and anything that needs a live Postgres connection or an
authenticated `ServerContext` — those are exercised manually / via the
seeded dev database, not vitest. If the logic you're adding needs a
database row to make sense, it's not a candidate for this suite; if it's a
pure calculation or state-machine transition, it is. `pnpm run test` (from
the repo root or `apps/web`) runs the whole suite; add `tests/<name>.test.ts`
alongside any new pure function in `lib/` or `server/services/`.
