# REST API v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only, versioned REST API (`/api/v1/{leads,accounts,persons,funnels,opportunities,quotations}`) authenticated by per-tenant API keys, enforcing the exact same RLS + permissions as the UI.

**Architecture:** An `api_keys` table + a `SECURITY DEFINER` `verify_api_key` function resolve a bearer key to `(tenant, member)` safely under RLS. `lib/api-auth.ts` builds a `ServerContext` from the key and exposes `withApiTenant(ctx, permission, fn)` that reuses the existing `assertCan` + `runInTenant` (the same RLS transaction the UI uses). Route handlers dispatch via a resource registry over shared readers extracted from the existing action query bodies. A minimal Settings page mints/revokes keys.

**Tech Stack:** Next.js 16 route handlers, Drizzle + Postgres RLS, Better Auth (existing), Node `crypto` (SHA-256), pnpm.

## Global Constraints

- **Same isolation as the UI, no exceptions.** Every data read runs through `runInTenant(ctx.tenantId, …)` (the `app.current_tenant` GUC, `crm_app` role) and `assertCan(ctx, PERMISSIONS.X_VIEW)`. No superuser/admin connection at request time except inside the `SECURITY DEFINER` function.
- **Read-only in v1.** No POST/PATCH/DELETE data endpoints. (Key management mutations are separate, gated server actions.)
- **Keys hashed at rest** (SHA-256), full key shown once at creation, revocable via `revoked_at`.
- **A key inherits its member's tenant + effective permissions** — never more.
- **CORS for the playground.** The `/api/v1/*` responses (and `/api/health`) must send `Access-Control-Allow-Origin` for the docs-site origin(s) + `Access-Control-Allow-Headers: authorization, content-type`, and answer the `OPTIONS` preflight, so the docs API Playground's "Send" works cross-origin. Bearer-token auth (no cookies) means this needs no `Allow-Credentials`. Allowed origins come from an env var (e.g. `API_CORS_ORIGINS`, comma-separated; default the docs vercel URL) — never `*` once keys are involved beyond the public health route.
- **Migration must be JOURNALED** — register the new SQL in `db/migrations/meta/_journal.json` (Drizzle journal-based migrator silently skips unregistered files).
- **Behavior-preserving refactor:** extracting shared readers from existing actions must not change UI behavior — the action keeps returning the same data.
- pnpm; verify `pnpm --filter web run typecheck/test/build`. Staging-first rollout (never straight to prod).

```sql
-- RLS: tenant-scoped like other tables.
ALTER TABLE api_keys ENABLE ROW LEVEL SECURITY;
CREATE POLICY api_keys_tenant ON api_keys
  USING (organization_id = current_setting('app.current_tenant', true)::uuid);
GRANT SELECT, INSERT, UPDATE ON api_keys TO crm_app;

-- Safe pre-tenant key lookup: returns only the minimal tuple for a live key,
-- and stamps last_used_at. SECURITY DEFINER so it bypasses RLS for THIS query
-- only; owned by the migrating role, EXECUTE granted to crm_app.
CREATE OR REPLACE FUNCTION verify_api_key(p_hash text)
RETURNS TABLE(organization_id uuid, member_id uuid)
LANGUAGE sql SECURITY DEFINER SET search_path = public AS $$
  UPDATE api_keys
     SET last_used_at = now()
   WHERE key_hash = p_hash AND revoked_at IS NULL
  RETURNING organization_id, member_id;
$$;
REVOKE ALL ON FUNCTION verify_api_key(text) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION verify_api_key(text) TO crm_app;
```

```ts
import "server-only"
import { createHash, randomBytes } from "node:crypto"
import { sql } from "drizzle-orm"
import { runInTenant, db, type Tx } from "@/db"
import { assertCan, type ServerContext } from "@/lib/server-context"
import type { PermissionKey } from "@/lib/permissions"

export function hashApiKey(key: string): string {
  return createHash("sha256").update(key).digest("hex")
}

export function generateApiKey() {
  const key = "qdk_" + randomBytes(24).toString("base64url")
  return { key, prefix: key.slice(0, 12), hash: hashApiKey(key) }
}

// Resolve a bearer key to the same ServerContext shape the UI uses.
export async function getApiContext(req: Request): Promise<ServerContext | null> {
  const auth = req.headers.get("authorization") ?? ""
  const m = auth.match(/^Bearer\s+(qdk_[A-Za-z0-9_-]+)$/)
  if (!m) return null
  const hash = hashApiKey(m[1])
  // SECURITY DEFINER fn: returns (organization_id, member_id) for a live key.
  const rows = await db.execute(
    sql`select * from verify_api_key(${hash})`
  )
  const row = (rows as unknown as Array<{ organization_id: string; member_id: string }>)[0]
  if (!row) return null
  // Load this member's effective permissions the SAME way getServerContext does.
  // <IMPLEMENTER: reuse the permission-loading query from lib/server-context.ts,
  //  parameterized by row.member_id + row.organization_id, returning Set<string>.
  //  Return a ServerContext { tenantId, memberId, roleName, permissions, ... }.>
  const permissions = await loadMemberPermissions(row.organization_id, row.member_id)
  return {
    tenantId: row.organization_id,
    memberId: row.member_id,
    roleName: permissions.roleName,
    permissions: permissions.set,
    // include any other required ServerContext fields with correct values
  } as ServerContext
}

export async function withApiTenant<T>(
  ctx: ServerContext,
  permission: PermissionKey,
  fn: (tx: Tx, ctx: ServerContext) => Promise<T>
```

```ts
import { NextResponse } from "next/server"
import { getApiContext, withApiTenant } from "@/lib/api-auth"
import { API_RESOURCES } from "@/lib/api-readers"

export const dynamic = "force-dynamic"

function err(code: string, message: string, status: number) {
  return NextResponse.json({ error: { code, message } }, { status })
}

export async function GET(
  req: Request,
  { params }: { params: Promise<{ resource: string }> }
) {
  const { resource } = await params
  const def = API_RESOURCES[resource]
  if (!def) return err("not_found", `Unknown resource '${resource}'`, 404)

  const ctx = await getApiContext(req)
  if (!ctx) return err("unauthorized", "Missing or invalid API key", 401)

  const url = new URL(req.url)
  const limit = Math.min(Math.max(parseInt(url.searchParams.get("limit") ?? "50", 10) || 50, 1), 100)
  const offset = Math.max(parseInt(url.searchParams.get("offset") ?? "0", 10) || 0, 0)

  try {
    const { rows, total } = await withApiTenant(ctx, def.permission, (tx, c) =>
      def.list(tx, c, { limit, offset })
    )
    return NextResponse.json({ data: rows, pagination: { limit, offset, total } })
  } catch (e) {
    // assertCan throws on permission denial
    return err("forbidden", "Your API key's role lacks permission for this resource", 403)
  }
}
```
